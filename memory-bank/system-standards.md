# System Standards

## Project Foundation & Context

- **MiniMart** is a Go modular monolith with an **Angular SPA frontend** and an **edge gateway**: product categories and catalog, stock reservation, shopping cart, wishlist, shipping quotes and shipments, checkout/orders, payments, customer profiles and addresses, avatars, notifications, AI-assisted review moderation, cookie-based authentication/RBAC, and a public showcase. One Go binary exposes **five roles** (`server`, `worker`, `migrate`, `gateway`, `dlq-replay`) selected by `os.Args[1]` in `backend/cmd/root.go` — no CLI framework, just a plain switch.
- Problems it solves: overselling stock under concurrency, safe retry of non-idempotent writes, event publication without a distributed transaction (transactional outbox), secure browser authentication and authorization, public product display, image upload/storage, shipping cost calculation and fulfillment tracking, moderated product reviews, a persistent per-customer cart that becomes an order, and a browser UI that consumes the API.
- Scope: **thirteen backend domains** — `address`, `auth`, `avatar`, `cart`, `catalog`, `category`, `customer`, `notification`, `order`, `payment`, `shipping`, `showcase`, `wishlist` — each under `backend/internal/<domain>/` with DDD layers (`domain/`, `application/`, `infrastructure/`, `presentation/`, `module.go`, `test/`). Seven publish contracts (`address`, `auth`, `catalog`, `category`, `customer`, `order`, `shipping`); `avatar`, `cart`, `notification`, `payment`, `showcase`, and `wishlist` publish none. `showcase` is a read-only HTTP domain, `cart` is HTTP-only and MongoDB-backed, `wishlist` is HTTP-only and MongoDB-backed, `avatar` is HTTP-only with S3 metadata, and `shipping` is Postgres-backed with HTTP, an `order-paid` consumer, and an outbox.
- The gateway is **not** a domain: it lives in `backend/cmd/gateway.go` + `backend/pkg/gateway/proxy` + `backend/pkg/cors`, boots no modules, and proxies to the server. There is no `backend/internal/gateway/` directory.
- The **frontend** is a standalone Angular application in `frontend/` (not part of the Go binary) that calls the API through the gateway with encrypted HttpOnly auth cookies.
- UX/API goals: predictable JSON under `/v1/...` with the shared response envelope (`backend/pkg/response`), Swagger outside production (`/swagger/`), Prometheus metrics at `/metrics`, and liveness/readiness at `/livez`/`/readyz` (`backend/pkg/health`). The gateway exposes its own health/metrics and adds CORS + optional rate limiting at the edge.
- Living behavioral specs live in `features/*.feature`; **no runner executes them**. The Insomnia collection at `backend/collections/minimart.collection.yaml` must be updated whenever an HTTP endpoint changes.

## Technology Stack

- **Language**: Go 1.27.4 (`backend/go.mod`); Docker builds pin `golang:1.27.3-alpine` (`scratch` runtime). CI uses one `GO_VERSION: '1.27'` value, not a version matrix.
- **Frontend**: Angular **21.2** + TypeScript **~5.9.2** (`frontend/package.json`), standalone components, **zoneless** change detection, signals, `@if`/`@for`, lazy `loadComponent` routes, functional guards/interceptors, `provideHttpClient(withFetch())`, and `provideAppInitializer()` restoring the session. Tests use **Vitest 4** (via the `@angular/build:unit-test` builder, runner default `vitest`) + jsdom 28; linting uses **ESLint 10** with **angular-eslint 21.4**; formatting uses Prettier 3 with printWidth 100 and single quotes. Package manager `npm@11.9.0`.
- **HTTP**: stdlib `net/http` + `ServeMux` with method/wildcard patterns (`mux.HandleFunc("GET /v1/orders/{id}", ...)`). No web framework.
- **Edge gateway**: `backend/cmd/gateway.go` wraps `httputil.ReverseProxy` (`backend/pkg/gateway/proxy`) with `backend/pkg/cors`, optional Redis rate limiting, and local `/livez`, `/readyz`, `/metrics`. It proxies all other paths to `GATEWAY_UPSTREAM` and forwards cookies/headers unchanged. Gateway depends on Redis for optional rate limiting. Listens on `GATEWAY_HTTP_ADDR` (default `:8080`).
- **Datastores** (`backend/docker-compose.yml`, `backend/conf/environment.go`):
  - PostgreSQL 16 (`pgx/v5`) — primary/replica split via `DATABASE_URL` / `DATABASE_REPLICA_URL`; sqlc queries.
  - MongoDB 7 (`mongo-driver/v2`) — notification records, per-channel deliveries, preferences, carts, and wishlists. `EnsureIndexes(ctx)` runs at module boot.
  - Redis 7 (`go-redis/v9`) — order/payment/shipping idempotency caches, server and gateway rate limiters, the RBAC permission cache, and the catalog review/rating read cache; always fail-open. Shared client wrapper lives in `backend/pkg/redis` (explicit dial/read/write/pool timeouts, `ContextTimeoutEnabled`). The shipping module uses the store for both quote creation (keyed `shipping:quote:<client key>`) and shipment creation from `order-paid` (keyed `shipping:shipment:<order id>`); the DB unique indexes (`shipping_quotes.idempotency_key`, `shipments.order_id`) remain authoritative when Redis is unavailable.
  - Kafka protocol via local Redpanda (`redpandadata/redpanda:v24.2.18`), using `IBM/sarama` + `ThreeDotsLabs/watermill-kafka` wrapped in `backend/pkg/kafka`. **17 source topics** (the 14 domain topics `order-placed`, `order-cancelled`, `order-stock-release`, `order-paid`, `payment-initiated|succeeded|failed|unknown|refunded`, `review-created`, `review-moderated`, `shipment-created|shipped|delivered`, plus the notification delivery topics `notification-email|sms|push`); `kafka.AllTopics()` is the canonical list and compose provisions a matching `<topic>.dlq` for each.
  - S3-compatible object storage for catalog images and avatars — local `floci/floci:latest-compat` (compose maps host `9000`/`9001` → container `4566`); AWS SDK v2 with path-style addressing and presigned GET URLs, wrapped by the shared client in `backend/pkg/storage/s3` (separate internal and browser-facing endpoints).
  - Ollama-hosted **Llama Guard 3** for review moderation via `backend/pkg/moderation/llamaguard`; optional and disabled unless `MODERATION_ENABLED` is set. Runs under docker-compose `--profile moderation`.
- **Key libraries**: `amacneil/dbmate/v2` (migrations), `swaggo/swag` + `http-swagger/v2`, `prometheus/client_golang`, `stretchr/testify`, `testcontainers-go` (+ `postgres`, `mongodb`, `redis`, `kafka` modules), `go.uber.org/goleak`, `golang-jwt/jwt/v5` (HS256), `golang.org/x/crypto` (bcrypt), `golang.org/x/sync/singleflight`, AWS SDK v2 (S3), `resend-go/v4` (email), `github.com/google/uuid`. Note: `aws-sdk-go-v2`, `resend-go/v4`, and `google/uuid` are **directly imported** by `backend/pkg/storage/s3`, `backend/internal/notification/infrastructure/email/resend`, and `backend/internal/catalog/application/review.go` even though `backend/go.mod` still lists them as `// indirect`.
- **Shared packages** (`backend/pkg/`): `auth` (JWT + AES-GCM cookies + middleware + `PublicRoutePaths`), `authz` (policy map, middleware, two-level permission cache), `background` (generic context-aware ticker runner for worker use cases), `backpressure` (pause/resume gate + pool monitor), `cors`, `country` (ISO-3166 alpha-2 normalization + `Equal`), `etag` (strong/weak ETag format/parse/match), `gateway/proxy`, `health` (liveness/readiness with critical vs non-critical dependencies), `idempotency` (port + generic `Coordinator[T]` + `redis` and `resilient` adapters), `kafka` (producer/consumer/retry/DLQ/replay/lag + `topics.go`), `logger` (slog setup, request-scoped logger, `X-Request-ID` middleware), `message` (event payload structs), `metrics` (96-method port + Prometheus implementation + `Noop`), `moderation` (provider port, noop provider, `llamaguard` adapter), `module` (+ `module/contracts`), `outbox` (+ `outbox/postgres` sqlc adapter), `ratelimit` (port + `redis` and `resilient` adapters), `redis` (shared client wrapper), `resilience` (in-process circuit breaker), `response` (shared envelope), `routes` (`Registrar` interface), `storage/s3`, `tests` (testcontainers helpers), `worker` (consumer/background-task host).
- **Tooling**: `make -C backend build|server|worker|migrate|gateway|dlq-replay|test|coverage|test-integration|lint|lint-fix|fmt|compose|compose-moderation|compose-down|compose-down-moderation|sqlc|new-migration|tidy|vuln|modernize|docs|build-pgo-gen|pgo-profile`. Generators are pinned Go tools: sqlc, dbmate, and swag. `make test` runs `go test -race -shuffle=on ./...`; `coverage` excludes `/cmd` and measures cross-package coverage with `-coverpkg`; `fmt` runs `golangci-lint fmt ./...` (gofmt + gofumpt); `modernize` fails if `go fix -diff` proposes changes.
- **PGO**: `build` automatically uses `default.pgo` when present; `build-pgo-gen` builds with `-pgo=auto`; `pgo-profile` warms a local server and generates the profile. CI's `pgo` job runs only on `main` pushes after `build`, starts compose, generates the profile, and uploads `minimart-pgo`.
- **Config**: env-only via `backend/conf/environment.go`; local defaults target compose. `backend/sample.env` documents variables. **No `.env` loading.** `COOKIE_DOMAIN` is the one exception: it is read directly with `os.Getenv` in `backend/cmd/deps.go:newCookieConfig` instead of through `conf`.
  - Core: `DATABASE_URL`, `DATABASE_REPLICA_URL`, `MONGO_URL`, `MONGO_DATABASE`, `SERVER_HTTP_ADDR` (`:8080`), `WORKER_HTTP_ADDR` (`:8081`), `GATEWAY_HTTP_ADDR` (`:8080`), `GATEWAY_UPSTREAM`, `ENV` (`development`), `LOG_LEVEL` (`info`), `LOG_FORMAT` (`json`).
  - Kafka: `KAFKA_BROKERS`, `KAFKA_CONSUMER_MAX_ATTEMPTS` (5), `KAFKA_CONSUMER_RETRY_BASE_DELAY` (500ms), `KAFKA_CONSUMER_RETRY_MAX_DELAY` (30s), `KAFKA_CONSUMER_RESTART_MIN_BACKOFF` (1s), `KAFKA_CONSUMER_RESTART_MAX_BACKOFF` (30s), `KAFKA_CONSUMER_CONCURRENCY` (1), `KAFKA_CONSUMER_PAUSE_ENABLED` (false), `KAFKA_CONSUMER_PAUSE_POOL_THRESHOLD` (0.9), `KAFKA_CONSUMER_PAUSE_DURATION` (5s), `KAFKA_CONSUMER_PAUSE_INTERVAL` (1s), `KAFKA_CONSUMER_LAG_ENABLED` (true), `KAFKA_CONSUMER_LAG_INTERVAL` (30s).

Both run as `65534:65534`, stop on SIGTERM, and contain only the binary, CA certs, and zoneinfo. Migrations are **not** in the image: `migrate` reads `./db/migrations` relative to CWD. Follow-up migrations merged in because the app is not productive yet.

## Coding Standards

- **File organization**: one test file per source file (`create_product.go` → `create_product_test.go`); one use case per application file; one handler file per endpoint. Pure data structs/ports need no unit test.
- **Repository adapters**: every domain has an in-memory `infrastructure/memory/repository.go` production package used by unit tests, plus its real adapter (Postgres reader/writer or MongoDB). All carry `var _ domain.Repository = (*Repository)(nil)`.
- **Test fakes never live in production files**: package helpers are `*_test.go`; this includes `backend/internal/<domain>/test/` helpers so `go build -tags=integration ./...` remains valid.
- **Naming**: singular lowercase package names; noun interfaces (`Repository`, `Provider`, `Limiter`); `New<Entity>`, `NewService`, `NewHandlers`; sentinel errors `Err<Condition>`; metrics `Inc<Event>` / `Observe<Thing>`.
- **Comments**: exported declarations get doc comments; unexported code gets comments only when logic is non-obvious; package comments live in `module.go` or `doc.go`. `revive` exported/package-comment rules are disabled.
- **Imports**: stdlib, third-party, `minimart/...`, blank-line groups; `net/http` is imported as `http`.
- **Frontend organization** (`frontend/src/app/`): `core/` singletons (ApiClient, auth store/service/refresh/guards/interceptor, toast, idempotency), `shared/` components/pipes/models, `features/<feature>/` routed components and API services. Path aliases `@app/*`, `@core/*`, `@shared/*`, `@features/*`. Standalone components, `inject()`, signals, SCSS, and `*.component|service|store|guard|interceptor|models|spec.ts` naming.
- **Gateway conventions**: edge-only — no domain logic, authentication, or authorization; the server remains the JWT/RBAC authority. Middleware belongs in `backend/pkg/` and is wired in `backend/cmd/gateway.go`.
- **Error handling**: wrap with `fmt.Errorf("context: %w", err)`; inspect with `errors.Is`/`errors.As`; sentinel errors for domain conditions; `nolint` needs an explanation and specific linter. Kafka handler errors are retried with bounded exponential backoff; exhausted or permanent failures are republished to `<topic>.dlq` with triage headers and then acknowledged. Failed DLQ publishes and shutdown leave the original unacked for redelivery.
- **Logging**: `log/slog` only, configured through `backend/pkg/logger`. `logger.Setup(logger.Config{Level, Format, Service, Version, Env})` runs in `backend/cmd/root.go` **before** the role switch and installs the logger with `slog.SetDefault`; JSON on stdout by default, `LOG_FORMAT=text` locally, and every record carries `service`/`version`/`env`. `logger.HTTPMiddleware` is the outermost server/gateway middleware: it honors or generates an `X-Request-ID`, puts a request-scoped logger in the context, and emits one `"http request"` line with `request_id, method, endpoint (r.Pattern), status, duration, bytes, remote_addr, user_agent` (5xx→error, 4xx→warn, else info; `GET /metrics`, `/livez`, `/readyz` are demoted to debug). Domain logs use `slog.InfoContext`/`WarnContext`/`ErrorContext`.
- **Context**: always first parameter, threaded through every layer, never stored in a struct.
- **Testing requirements**:
  - Unit tests: table-driven `t.Run` subtests, `testify/assert` + `require`, local fakes, `metrics.Noop{}`, and `goleak.VerifyTestMain`.
  - `usetesting` requires `t.Context()` over `context.Background()`/`TODO()` and `t.TempDir()`.
  - Integration tests: `//go:build integration`, one `TestMain` per `backend/internal/<domain>/test/` package using testcontainers via `pkg/tests`; only the needed containers start (cart needs MongoDB only; avatar adds MinIO/S3). `backend/pkg/tests` deliberately does **not** import `testing` — `TestMain` drives it. Container images: `postgres:16-alpine`, `mongo:7`, `redis:7-alpine`, `confluentinc/confluent-local:7.5.0`, and `ghcr.io/coollabsio/minio:RELEASE.2025-10-15T17-29-55Z` for S3 (MinIO no longer publishes to Docker Hub). Run with `make test-integration` (`go test -count=1 -timeout=20m -tags=integration ./internal/...`).
  - CI runs unit tests with race/shuffle, integration tests, `golangci-lint` with `--build-tags=integration`, `govulncheck`, `go fix` modernization, and a build. `build` needs `lint`, `test`, and `vuln`; PGO is a separate main-only job. The SPA has its own gate in `.github/workflows/frontend.yml` (Node 24, `npm ci`, ESLint via angular-eslint, Prettier check, Vitest, production build).
  - **`id_test.go` standard**: shape (non-empty, `len(id) >= 26`, base32 `^[A-Z2-7]+$`) and uniqueness (1000 draws); `assert` for shape, `require` for uniqueness, no `t.Parallel()`.
- **Linting**: strict `backend/.golangci.yml` (schema `version: "2"`), golangci-lint **v2**; CI uses `golangci/golangci-lint-action@v7` with `version: v2` and integration build tags. 38 linters enabled, including errcheck (with type-assertion checks), gosec, errorlint, noctx, bodyclose, sqlclosecheck, rowserrcheck, sloglint, loggercheck, testifylint, thelper, usetesting, modernize, nolintlint (explanation + specific), `govet` with `shadow`, `gocritic`, `perfsprint`, `forcetypeassert`, `nilerr`, `exptostd`, `intrange`, and `usestdlibvars`. `revive`'s `exported` and `package-comments` rules are disabled. Formatters: **gofmt + gofumpt** (no goimports/gci); generated files are exempt (`generated: lax`) and `third_party$`/`builtin$`/`examples$`/`docs$` are excluded.
- **Documentation**: every HTTP handler has Swagger annotations; regenerate with `make docs`. Docs are hidden when `ENV=production`. `AGENTS.md` remains the canonical agent-facing spec.
